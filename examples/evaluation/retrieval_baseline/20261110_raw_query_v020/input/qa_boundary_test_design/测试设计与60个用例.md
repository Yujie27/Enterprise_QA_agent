# 企业知识问答 Agent：修改前测试设计与边界用例

设计日期：2026-11-10。共60个编号用例、28份合成资料文件。**所有真实模型用例均为未执行。**本包只生成测试设计和资料，不修改原项目，不包含运行器，不代表已经取得测试结果。

## 1. 先明确评分对象

题目要求：可靠回答、文档ID和原文引用、资料缺口、任务状态；基于工具结果动态选择补充检索、读取原文、追问或停止；资料冲突时说明并查证，不任意选择。必须覆盖明确答案、文档冲突、资料外问题、改写相似问题、上下文追问、工具失败。至少三组实际输入/输出/Trace覆盖正常、资料不足、工具失败，并覆盖所有验收点；至少两条运行路径展示模型根据不同工具结果调整动作。Mock只验证流程。

以原题为准：D01写30日、D02写15日，未给适用范围/优先级时，须列冲突并请求确认；只检索到D01且未发现矛盾时，可以按D01答30日并限定证据范围。不能为了冲突测试而把所有单证据场景都判为必须拒答。

## 2. 论文依据与适用边界

下面是测试维度的研究依据。本包60个用例、企业制度分类、优先级及判分规则由本项目场景改编设计，不是任何论文的原始基准，也没有复现论文指标。

- **RGB**：Benchmarking Large Language Models in Retrieval-Augmented Generation，AAAI 2024。[原文](https://arxiv.org/abs/2309.01431)。噪声鲁棒性、无答案拒答、信息整合及反事实鲁棒性；本文用例是企业制度适配，未复现RGB全套基准。
- **DRAGged**：DRAGged into Conflicts: Detecting and Addressing Conflicting Sources in Search-Augmented LLMs，arXiv 2025。[原文](https://arxiv.org/abs/2506.08500)。区分冲突类型及相应回答行为。企业制度的适用范围、替代关系分类属于本测试设计。
- **ConfRAG**：Benchmarking LLM’s Capability in Reasoning over Conflicting Web References，ACL 2026。[原文](https://aclanthology.org/2026.acl-long.11/)。评估答案聚类、答案覆盖和理由覆盖；用于启发冲突双方及解释覆盖检查。
- **LostMiddle**：Lost in the Middle: How Language Models Use Long Contexts，TACL 2024。[原文](https://aclanthology.org/2024.tacl-1.9/)。相关证据在长上下文不同位置的性能差异。
- **MultiChallenge**：MultiChallenge: A Realistic Multi-Turn Conversation Evaluation Benchmark Challenging to Frontier LLMs，Findings of ACL 2025。[原文](https://aclanthology.org/2025.findings-acl.958/)。多轮指令保持、信息记忆及上下文一致性。
- **ALCE**：Enabling Large Language Models to Generate Text with Citations，EMNLP 2023。[原文](https://aclanthology.org/2023.emnlp-main.398/)。引用质量评估；实际片段是否支持断言及回答是否有充分引用。
- **BIPIA**：Benchmarking and Defending Against Indirect Prompt Injection Attacks on Large Language Models，KDD 2025；预印本2023。[原文](https://arxiv.org/abs/2312.14197)。工具/资料中的指令与可信控制指令的边界。
- **BetterTogether**：Better Together: Complementary Query Rewriting Under a Strong RAG Baseline，EMNLP 2026 Industry。[原文](https://aclanthology.org/2026.emnlp-industry.143/)。查询改写互补性及选择性触发；其路由为模拟评估，不将论文数值当本项目指标。

本包涉及的期限、日期、产品功能全部为合成规则；不表示真实企业制度或法律规则。反事实改动用于检查答案是否随当前测试资料改变，不能推广为现实中盲信任意检索资料。

## 3. 三层测试，定位真正的失败来源

| 层次 | 输入 | 核验内容 | 解释边界 |
|---|---|---|---|
| 检索层 | 原问题/改写问题 + 固定corpus | 相关条款是否进入候选、冲突双方是否完整进入 | 漏召回不能归为模型看见证据仍误判 |
| 受控证据层 | 给模型固定、记录过的工具返回，确保关键条款可见 | 冲突分类、引用、追问、拒答、位置偏差 | 此层证明给定证据下的行为，不证明真实检索能力 |
| 端到端层 | CLI真实模型 + 本地工具 + 故障配置 | 自主工具循环、最终答案、限制、Trace | 验收所需的模型动态决策证据来自此层 |

按生产路径直接运行的语料可通过--corpus切换。F03/F05/F07/F09、M08、X09以及工具顺序/候选位置控制，需要之后接入受控适配器；当前CLI仅有整类工具失败开关，不能宣称所有故障已可直接运行。模型桩验证协议，必须与真实模型Trace区分。

把解压目录qa_boundary_test_design置于仓库根目录后，示例命令为：

```powershell
uv run --locked enterprise-qa --corpus qa_boundary_test_design/corpora/single.json "报销期限多久？"
uv run --locked enterprise-qa --corpus qa_boundary_test_design/corpora/conflict.json "报销期限多久？"
uv run --locked enterprise-qa --corpus qa_boundary_test_design/corpora/scoped.json --interactive "报销期限多久？" --follow-up "研发部门，差旅报销。"
uv run --locked enterprise-qa --corpus qa_boundary_test_design/corpora/single.json --simulate-failure search_docs "报销期限多久？"
```

检查README中的当前入口和.env配置后再执行。无可用模型可以用Mock看流程，但不可据此填写真实模型效果。一个复合用例的首/中/尾、k/k+1、异常类型、重复运行要分别存结果，再汇总，不能只挑成功变体。

## 6. 全局判定规则

1. 每条制度性结论均须由模型本次实际可见资料支持。只碰巧答对数字、引用错文档，仍不通过引用正确性。
2. 检查文档ID、section、版本日期和原文片段。可接受不改变含义的空格/标点规范化；不得删掉否定、范围、单位、起算点或例外。缺失的元数据须明示，不补造。
3. 只要求动作的必要约束。例如冲突需核验范围和依据，不强制工具次数、查询原句或唯一动作顺序；充分的工具片段可以支撑回答。
4. 连续无结果后停止、补查原文、追问属于不同的有效策略，按用例是否取得必要证据判断。工具故障不能等同库里没有规定。
5. 工具请求被拒绝不能描述为执行成功。模型未触发预定故障工具时，标“路径未触发”，不能记作通过故障场景。
6. 区分执行结果与业务结果：执行可正常完成，但业务需澄清/冲突未解/资料不足。当前completed只指流程结束时，不凭这个单字段判业务成功；保存人工判定的业务结果。
7. 部分可答时回答可答部分并列资料缺口，不能因答对主结论就忽略附带幻觉。
8. 首次请求空白、非法预算、损坏文件属于输入/数据工程错误；X10属于数据完整性扩展项，可加载时明确拒绝，不能要求系统强行回答。

## 8. 变形关系：修改资料后应当如何变化

| 对照 | 只改变什么 | 应当变化 | 应保持 |
|---|---|---|---|
| R01 ↔ X06 | D01期限30→45 | 答案数字30→45，原文跟随 | 正确引用当前D01，正常回答 |
| C01 ↔ C02 | 移除冲突方D02 | 冲突追问→据D01答30 | 不编造其他资料 |
| C01 ↔ X04 | 文档/工具返回顺序 | 展示顺序可变 | 仍识别双方，不任意选数 |
| C01 ↔ X05 | 文档及条款ID | 引用ID随之变化 | 冲突判断不变 |
| C01 ↔ C13 | 增加某方转载副本 | 可去重/提示转载 | 无新增优先级，仍保留冲突 |
| C01 ↔ C05 | D02日期较新 | 说明日期差异 | 无替代依据仍不能选新 |
| C06 ↔ C07 ↔ C08 | 费用发生时间 | 按明确过渡条款选择 | 不按运行当天套规则 |
| E06 ↔ E07 | 截止边界前后1秒 | 按时→逾期 | 依合成规则计算，不加假设 |

编号重命名会改变当前检索的同分排序，因此同时记录候选列表。调换文件顺序可能被排序抵消；位置测试必须确认实际工具返回/模型输入位置确实改变，否则记为未触发变换。

## 9. 极端测试如何增加强度

- 噪声：1条必要证据+0/9/49/99条噪声；逐级观察退化，不要求有限预算系统在任意规模下必过。
- 位置：相关条款在等长文档首/中/尾；多文档上下文也可置于首/中/尾，保留相同材料和总长度。
- 截断：冲突方分别位于Top-k的k与k+1位；同时做召回层和固定双证据的受控模型测试。
- 重复：冲突一方副本数0/1/8/20；明确copied_from，不能把转载数当权威。
- 查询长度：短问法、完整问法、夹杂无关句、错字和中英混合；长输入若超配置限制，应明确报错或请求精简。
- 工具：失败首次/连续/恢复、空列表/null/畸形、预算B内完成与B+1被拒；每种异常单独运行。
- 时间：生效前/当日/后；对截止边界，只在资料明确起算和截止含义时要求精确日期结果。

## 10. 评估指标与记录

| 指标 | 定义/用途 |
|---|---|
| 必要证据Recall@k | 召回的标注必要条款数 / 本题全部必要条款数；单位为doc_id+section_id |
| 冲突双方完整召回率 | 需双方证据的冲突问题中，所有必要冲突条款都进候选的比例；项目自定义指标 |
| 冲突处理正确率 | 该报冲突、可按范围区分、明确替代可裁决、互补可合并各类分别计数，再给宏平均 |
| 证据支持率 | 有依据的制度断言数 / 全部制度断言数；零断言不自动算100% |
| 引用覆盖与正确性 | 哪些事实结论有引用、引用是否支持该结论；无证据题无需强造引用 |
| 合理拒答与过度拒答 | 缺证据时拒答/澄清比例，以及可答题被拒答的比例，分开报告 |
| 资料变化敏感性 | R01/X06等成对用例是否按预期改变；顺序/ID变换则检查保持性 |
| 动作与成本 | 调用数、重试数、延迟、token(可获取时)、结束原因；达到预算不掩盖未完成 |

不要直接用回答字符串相等判通过；可先核对数字、ID和原文，再人工检查适用范围、否定、时间单位和额外断言。LLM裁判只能辅助；冲突裁决与引用关键缺陷须人工复核。

每次至少保存：case_id、variant_id、commit SHA、语料SHA256、模型名称/服务、温度及其他采样配置、可用时seed、工具预算、原始工具返回、最终答案、Trace路径、人工业务判定、失败原因、时延。不要保存密钥。记录decision_reason等公开理由即可，不记录内部思维过程。

## 11. 修改前后如何公平比较

1. 先固定当前提交、语料和用例，跑基线；保留失败原样，不先修正数据来让基线通过。
2. A=当前检索；B=A+按需改写；C=B+关联冲突证据补查；D=C+分类处理。保持模型、数据和预算一致；若确需改变预算，另列成本匹配对照。
3. 用开发子集调参数，保留一组事先不参与调参的验收题；同一原题的改写/改数等变体按组分配，防止两边泄漏。
4. 重要真实模型用例建议重复3次，报告每次和通过次数，不能只取最好的一次。预算有限则先单次、诚实标注。
5. 不把60个设计项都当独立统计样本；同组变体相关，样本量小不宣称有统计显著性。
6. 先给各类通过数/总数和关键失败实例，再报告总体数。不能让大量简单题掩盖冲突任意裁决、错引原文等关键缺陷。
